### Corrections to the research plan

| # | Research plan says | What I found | Decision |
| --- | --- | --- | --- |
| 1 | Input about 504x315, "for example 504x308" by cropping | The API default `upper_bound_resize` gives 315, a tie between 308 and 322, and the tie rounds **up**: **504x322**, non-uniform | Use 504x322 everywhere, so fine-tuned and zero-shot inputs are identical. K scales by sx=504/1920, sy=322/1200. Task 3 confirms it at runtime |
| 2 | Use the same `lambda_c` as the DA3 paper | The paper gives the equation but **does not state a value** (section 3.3) | Treat `lambda_c` as a Phase 3 hyperparameter chosen on validation |
| 3 | Overfit check: "loss should fall to near zero" | `c*e - lambda*log(c)` is unbounded below, so that check can't work | Judge the overfit check on AbsRel, not the loss |
| 4 | (Not considered) | `depth_conf` is `exp(x)+1`, so c >= 1. The optimum is c = max(1, lambda/e), so every pixel with error above lambda sits at the floor and is not ranked | Choose `lambda_c` above the 0.25 high-error threshold, or check the confidence histogram on validation |
| 5 | Gradient checkpointing "if batch 4 doesn't fit" | The DA3 ViT block loop has no checkpointing | Add our own wrapper in Task 4 |
| 6 | Download table lists the Ouster scans only | Labels are a **separate 174 MB download**. Image annotations cover only 6,235 of 13,556 frames, so every-5th-frame evaluation would often have no 2D labels | Download the Ouster labels. Phase 1 uses per-point labels for terrain, which label every valid GT pixel, and cross-checks them against the image annotations |
| 7 | Conda | Not installed in WSL. C: has only 14.9 GB free, but the WSL disks are on N: (126 GB free) | Use uv inside WSL. Nothing goes on C: |

### Traps found in the DA3 source (each pinned by a test)

- A list passed to `api.inference()` is treated as **multi-view** (`(1, N, 3, H, W)`). Batches must go in as `(B, 1, 3, H, W)`.
- `DepthAnything3.forward` is wrapped in `inference_mode`. The trainable path is the inner `DepthAnything3Net`, which has no such wrapper.
- `patch_embed.proj` also matches "proj", so the peft target must be a regex scoped to `blocks.N.attn`.
- The head always runs its ray branch. Those parameters never receive gradients and must be frozen by name.
- The head runs with autocast **disabled**, so bf16 applies to the backbone only. Head VRAM use is therefore float32.

Still to settle in Phase 3: the distillation L1 on median-normalised linear depth is likely to be dominated by far and sky pixels, since DA3-Small has no sky clamp. Log-space is the probable fix. Logged in `DECISIONS.md`, no code now.

## Global Constraints

- `config.yaml` is the single source of truth; scripts take no hard-coded paths or thresholds.
- Fixed seeds everywhere; every expensive step caches to `.npz`.
- Input 504x322; patch size 14; ImageNet normalisation through upstream `InputProcessor`, never reimplemented.
- bf16 autocast on the backbone, matching upstream.
- Never resize depth maps by interpolation; never upsample predictions.
- Target distro is `Ubuntu`. `Ubuntu-26.04` belongs to another project; do not touch it. Do not change `.wslconfig`.
- RELLIS is CC BY-NC-SA 3.0; data and weights are never committed to git.

## Review Focus

1. Google Drive returns a quota HTML page instead of a zip: fail clearly and name the file for manual download (test in Task 2).
2. A sequence has images without scans, or missing labels: `verify_rellis` reports it and exits non-zero (test in Task 2).
3. OOM during a VRAM measurement: record `OOM` in the CSV and carry on with the next configuration (test in Task 5).
4. Multi-frame calls silently becoming multi-view: the batch test proves each frame is independent (test in Task 3).
5. Desktop apps holding VRAM skew the numbers: record free VRAM per row (test in Task 5).

### Task 3: Trainable DA3 forward pass that matches the API

**Files:** Create `src/models.py`, `tests/test_models.py`

**Interfaces:** Produces:
- `load_da3(hf_id: str, device: str) -> DepthAnything3`
- `preprocess(images: list, process_res: int = 504) -> Tensor (B, 3, H, W)`, calling upstream `InputProcessor` with `upper_bound_resize` per image
- `forward_da3(net: DepthAnything3Net, x: Tensor (B,3,H,W)) -> dict` with `depth (B,H,W)`, `conf (B,H,W)`. Gradients are enabled and `cam_dec` is skipped. Calls `net.backbone(x[:, None], cam_token=None, export_feat_layers=[])` under bf16 autocast, then `net.head(feats, H, W, patch_start_idx=0)` with autocast disabled, mirroring `DepthAnything3Net.forward`.

Tests use the first frame of each sequence, or a 1920x1200 noise image if extraction hasn't finished. Mark them `gpu`.

- [ ] **Step 1:** Write the tests:
  - `test_output_size`: a 1920x1200 input gives depth and conf of shape `(322, 504)`.
  - `test_forward_matches_api`: `forward_da3` under `no_grad` vs `api.inference([path]).depth`/`.conf`: max relative difference `< 1e-4`. This closes the preprocessing-match item. If it fails, find the cause; do not loosen the tolerance.
  - `test_batch_is_independent`: two different frames as `(B=2)` vs one at a time: max relative difference `< 1e-2`. This proves batching isn't multi-view.
  - `test_multiview_differs`: a `(1, 2, ...)` input gives a different result from `(2, 1, ...)`, confirming the trap is real.
  - `test_gradients_reach_depth_and_conf`: `depth.requires_grad and conf.requires_grad`, and backward gives a non-zero grad on a backbone block.
  - `test_conf_floor`: `conf.min() >= 1`.
- [ ] **Step 2:** Run and confirm they fail, implement, run and confirm they pass. Command: `pytest tests/test_models.py -m gpu -v`.
- [ ] **Step 3:** Commit.

### Task 4: Fine-tuning modes

**Files:** Modify `src/models.py`, `tests/test_models.py`

**Interfaces:** Consumes `forward_da3`. Produces:
- `set_trainable(net, mode: Literal["head", "lora", "full"], lora_rank: int = 8, target_regex: str = ...) -> None`. Freezes all parameters, then: `head` enables head parameters except the ray branch (names containing `_aux`; confirm against `dualdpt._fuse` while implementing); `lora` adds `peft.inject_adapter_in_model` on `net.backbone` plus the head as above; `full` adds the whole backbone plus the head as above. `cam_enc` and `cam_dec` stay frozen in every mode.
- `enable_checkpointing(net) -> None`: wraps each `blk.forward` in `net.backbone.pretrained.blocks` with `torch.utils.checkpoint` (`use_reentrant=False`).

- [ ] **Step 1:** Write the tests:
  - `test_lora_param_count`: LoRA parameters equal `27648 * rank` (12 blocks, each `qkv` 384→r→1152 plus `proj` 384→r→384).
  - `test_lora_skips_patch_embed`: no `lora_` parameter under `patch_embed`.
  - `test_every_trainable_param_gets_grad`: parametrised over all modes; after one backward, no parameter with `requires_grad` has `grad is None`. This catches ray-branch leaks.
  - `test_frozen_params_unchanged`: after one AdamW step in `head` mode, a backbone block is unchanged.
  - `test_lora_starts_identical`: `lora` output at initialisation matches the original within `1e-5`.
  - `test_checkpointing_same_output`: the same output with and without `enable_checkpointing`, within `1e-4`.
- [ ] **Step 2:** Run and confirm they fail, implement, run and confirm they pass.
